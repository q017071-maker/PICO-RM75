# RM75–PICO 跨设备部署与操作手册

本手册对应2026-11-06连续摇杆平移版。先完成软件、输入与只读检查，再由现场操作员手动启用运动。准备脚本、测试和APK构建不连接机械臂；`*-live`、`live-6dof`和`joystick-continuous`为实控入口。

## 1. 设备和版本

| 项目 | 当前使用/要求 |
|---|---|
| 电脑 | Ubuntu24.04 x86_64，Wi-Fi + 独立有线网口，NetworkManager |
| 头显 | PICO4 Ultra、左右控制器，开发者模式和USB调试已开启 |
| 机械臂 | RM75，7轴，当前现场为6FB传感器、控制器版本3 |
| Python | 3.12；`robotic-arm==1.1.6`、`pytest==7.4.4`，见requirements |
| Unity | 2022.3.62f3，启用授权；Android Build Support、SDK/NDK Tools、OpenJDK |
| PICO SDK | PICO Integration3.4.0；不要换成PICO Unity OpenXR SDK |
| Android | ARM64、IL2CPP、GLES3、min API29 / target API34；安装Android34平台 |
| ROS | 不需要；入口用`-E -s`隔离已有ROS的Python环境变量 |

Python原生SDK仅在这套Linux x86_64环境验证；其他操作系统、ARM电脑或其他控制器型号不能直接照搬。RM65是迁移历史名称，当前入口校验实际型号RM_75和7轴，不能仅改文件名适配其他机械臂。

## 2. 下载与准备

```bash
git clone https://github.com/q017071-maker/PICO-RM75.git
cd PICO-RM75
bash 准备电脑.sh --python-only
```

准备脚本用普通用户运行；仅缺少系统venv包时调用sudo，Python包安装在`project/.venv`内。不安装ROS，不自动配置网络或启用运动。若要固定本次交付，克隆后运行 `git switch release/2026.11.06-continuous`（版本分支）；需要严格固定时记录并checkout该版本的提交SHA。不要从其他电脑直接复制`.venv`，应重新创建。

通过Unity Hub安装并授权Unity2022.3.62f3和Android模块。默认安装位置：

```text
~/Unity/Hub/Editor/2022.3.62f3/Editor/Data
```

如果安装路径不同，在每个相关终端设置：

```bash
export UNITY_EDITOR_DATA='/实际位置/2022.3.62f3/Editor/Data'
```

从[PICO官方资源](https://developer.picoxr.com/resources/?platform=unity)或[官方SDK仓库](https://github.com/Pico-Developer/PICO-Unity-Integration-SDK)取得**3.4.0**，解压。把含`package.json`的包根目录放到：

```text
PICO-RM75/deployment/vendor/PICO_Unity_Integration_SDK_3.4.0/package.json
```

包名应为`com.unity.xr.picoxr`，版本为`3.4.0`。不能在这个目录里再套一层压缩包文件夹。项目manifest和lock均使用该相对路径，SDK本体不放入本仓库。Unity首次打开还需要访问Unity Package Registry下载manifest/lock中的包；不依赖原电脑的Library缓存。

## 3. 验证源码、配置Unity并构建APK

无设备Python检查：

```bash
project/.venv/bin/python -E -s -m pytest -q project/tests deployment/test_pc.py
project/.venv/bin/python -E -s project/scripts/rm75_continuous_offline.py
```

Unity已安装后，运行全部离线检查：

```bash
bash 启动.sh test
```

在普通Ubuntu终端打开最新工程：

```bash
bash 打开Unity.sh
```

Unity Hub手动添加项目时选择**仓库内的`project/`子目录**。等待包下载/导入完成；自动配置入口会设置Android/PICO loader、`Assets/Scenes/SampleScene.unity`、RM75模型、位姿发送器和双摇杆发送器，不进入Play模式。菜单在Unity顶部菜单栏 **RM75 → Configure Current Project** 和 **RM75 → Build Android APK**，不是Unity Hub的菜单。

Unity关闭时也可构建：

```bash
bash 启动.sh build-apk
```

若工程已被Unity占用，使用该窗口的RM75构建菜单。勿因为有旧UnityLockfile就删除锁或打开第二个编辑器；现在由Unity自身判断占用。若命令报199/授权服务无法连接，在正常桌面会话打开Unity Hub完成授权，再从同一用户的普通终端构建。

成功后生成`project/Build/PICO_RM75_Teleop.apk`、`deployment/logs/apk-build.json`和`unity-project-config.json`。这些构建证明包含当前电脑路径和源码哈希，应在新电脑本地生成，不复制旧报告伪装为已构建。运行：

```bash
bash 启动.sh doctor --offline
```

首次未配置Unity/SDK或未构建APK时显示MISSING是预期的；按提示补齐。`doctor --offline`只检查接口/文件，不创建机器人对象。原五个稳定核心的SHA应与`deployment/deployed-source-manifest.json`一致。

## 4. 接线和网络

- 机械臂以网线直连电脑；默认机器人`192.168.1.18:8080`，电脑有线`192.168.1.100/24`。
- PICO和电脑连接同一Wi-Fi，避免访客网络/AP隔离。Wi-Fi网段不能和机械臂有线`192.168.1.0/24`重叠。
- USB用于安装、授权和写入电脑地址。当前APP的手柄UDP数据仍走Wi-Fi；只插USB不代表UDP通了。

查当前有线接口名称（新电脑不一定叫eno2）：

```bash
nmcli device status
bash 启动.sh configure-ethernet --interface 实际有线接口名
```

命令创建/更新专用NetworkManager配置，不接管默认路由、不删除其他连接，也不连接机器人。若机器人地址已更改，网络配置的`--robot-ip`、`--pc-cidr`和后续实控的`--robot-ip`必须对应调整；这些参数只设置本机或程序目标，不更改机器人IP。

| 数据 | 方向/端口 |
|---|---|
| 右手柄位姿、Grip、真实追踪诊断 | PICO→电脑 UDP5005 |
| 左右摇杆primary2DAxis | PICO→电脑 UDP5007 |
| 摇杆虚拟位姿 | 桥接器→127.0.0.1 UDP5008 |
| 机械臂实测关节显示 | 127.0.0.1 UDP5006→桥接器→PICO UDP5006 |
| 机器人控制SDK | 电脑有线→机器人 TCP8080 |

5008只在本机使用。若启用防火墙，应允许PICO来源到电脑UDP5005/5007和电脑到PICO5006；不要直接关闭防火墙。原始UDP未做身份认证，桥接器识别锁定一个来源IP并不能替代可信局域网。

## 5. 安装PICO应用并确认输入

USB连接PICO，在头显内确认调试授权；若Linux报USB权限错误，应按PICO/Android官方设备规则配置udev，不以root启动整套程序。

```bash
bash 启动.sh install-apk
```

它检查新版APK构建证明，安装应用，自动检测电脑Wi-Fi地址写入头显`ubuntu_udp.txt`，再打开应用。包名为`com.DefaultCompany.PICO_RM75_Teleop`，本版versionCode为20261107。以后电脑Wi-Fi地址变化，只需USB连接后：

```bash
bash 启动.sh configure-pico
# 多网卡无法唯一确定时，--host 填电脑Wi-Fi地址（不是PICO地址）：
bash 启动.sh configure-pico --host 电脑WiFi_IP
```

输入检查完全不加载机械臂SDK：

```bash
bash 启动.sh input --seconds 30
```

戴好头显、进入APP、唤醒控制器，松开再按右Grip并缓慢移动。应收到`valid=True tracking_verified=True`，Grip在0和1间变化。收到0包时先查APP前台、佩戴/休眠、同Wi-Fi、IP、AP隔离和防火墙。此命令占用5005，测试后退出再启动桥接器。

换电脑重新构建使用另一把调试签名时，可能出现`INSTALL_FAILED_UPDATE_INCOMPATIBLE`。先核对包名和签名；只有确定允许丢弃旧APP数据后才在PICO上卸载旧版本再装，随后重新configure-pico。不要把原电脑签名密钥上传GitHub。

## 6. 日常启动：两个终端

两个终端都进入同一个仓库主目录，PICO保持前台和有效追踪。

终端一：

```bash
bash 启动.sh joystick-bridge
```

松开Grip，等待“已识别并锁定PICO”。桥接器从同一来源IP的新鲜摇杆流和追踪有效、Grip已释放的位姿流配对；不需要手工填写PICO IP。每秒`INPUT axes(lx,ly,rx,ry)=... base_hz=... stick_hz=...`帮助检查输入。50Hz是配置目标，不能据此宣称零丢包或端到端延迟。换PICO/IP需重启桥接器；可选`--pico-ip PICO_IP`固定来源。

首次接线先在终端二只读检查：

```bash
bash 启动.sh joystick-preview
```

此预览会连接机器人读取状态，但不发运动；没有机器人用`joystick-offline`或连续离线脚本。观察拨杆四轴分别改变TARGET；按住Grip时移动实际手柄不应改变摇杆目标。这个旧预览保留25cm范围，不能用其边界判定连续模式总行程。

通过输入和预览检查后，松Grip、Ctrl+C退出预览，终端二运行：

```bash
bash 启动.sh joystick-continuous
```

若机器人不是默认地址，加`--robot-ip 实际机器人IP`。检查读取到的RM_75/7轴和绝对关节安全边界，在提示处手动输入：

```text
MOVE_RM75_CONTINUOUS
```

禁止用管道自动确认。先释放右Grip等READY，两摇杆居中再按住Grip；先做短距离单轴、回中和释放停止检查，再延长运动。控制台`lead_limit=0.005m`表示目标可超前实测约5mm，**不是末端总行程只有5mm**。

| 摇杆 | 暂定基坐标方向 |
|---|---|
| 左上下 | X正负 |
| 左左右 | Y正负 |
| 右上下 | Z正负 |
| 右左右 | 绕基坐标X轴旋转 |

实际视觉正负需标定，不能假设“屏幕上方”就是机器人前方。非零初始姿态时，基坐标X旋转可能同时改变多个打印Euler角。启动时读取控制器当前工具/工作坐标并同步本地Algo；不写机器人坐标系或限位。

## 7. 运动边界与停止

连续模式同一次Grip没有25cm平移半径或30°累计关节预算，使用当前测量与逐帧摇杆增量持续推进。摇杆回中停止增加目标；机械臂仍可能收敛到最后接受的目标，所以不能仅凭TARGET固定判定物理停止。松Grip执行原停止流程，只按Grip未拨摇杆时不发运动。

保留/新增的保护：

- 控制器与SDK模型绝对关节限位取交集、5°裕量；每个IK候选相对实测关节单步≤3°；奇异性阈值0.01。
- 最大平移5cm/s；基坐标X旋转0.05rad/s、每次Grip姿态范围10°、姿态跳变3°。
- 包/状态超时0.25秒、摇杆超时0.20秒、原位置误差1.5cm、关节与姿态跟踪保护保持；无进展约1秒停机。
- 目标超前缓冲约5mm，不积累未执行位移；可恢复的HOLD后反向拨杆可退回，不必松Grip清除平移积压。
- 新会话、来源变化、无效追踪或失联必须先释放Grip才能重新使能；不伪造tracking_verified。

`HOLD`看原因：奇异、不可达或安全限位时可反向退回；旋转超过10°时也会HOLD。`WAIT_RELEASE`/`DISARM`必须先释放Grip并排查故障。固定姿态/当前肘部构型可能提前遇到奇异或不可达，不能保证沿任意直线到达机械硬止挡；本项目没有新增环境碰撞检测或自动绕障。

运动空间留空、急停可触及，首次实测分短段进行。正常结束先松Grip，再Ctrl+C退出终端二，最后退出桥接器；异常运动或停止失效时使用物理急停。不要增大奇异性阈值、关闭超时或使用此前失败的J4软限位补丁。

## 8. 切换模式和回退

各控制入口共用input.lock/UDP端口，不能叠加。切换前先松Grip并退出旧控制程序。

| 模式 | 终端一 | 终端二 | 手动确认 |
|---|---|---|---|
| 连续摇杆 | joystick-bridge | joystick-continuous | MOVE_RM75_CONTINUOUS |
| 旧预算摇杆 | joystick-bridge | joystick-live | MOVE_RM75_JOYSTICK |
| 原6DoF跟随 | 关闭桥接器 | live-6dof | MOVE_RM75_6DOF |
| 原6DoF只读 | 关闭桥接器 | orientation-preview | 无 |

表中命令均以`bash 启动.sh`为前缀。旧摇杆入口仍是25cm半径、每次Grip关节累计30°，可用于对照回退。原6DoF使用原稳定源码与参数，不受连续模式的累计预算调整影响。

更新前退出所有控制程序，记录当前提交 `git rev-parse HEAD`；工作树有改动先单独保存，再使用`git pull --ff-only`，不强制覆盖。Python控制更新通常无需重建APK；C#、场景、Packages或ProjectSettings改变后应重建安装。切回历史版本会恢复当时全部代码，需要重新验收且可能需重建APK。

## 9. 日志、回放和验收

日志自动保存在`deployment/logs/`，不纳入Git。连续日志类型`rm75_continuous_joystick_log`，包含目标、运动结果、发送计数、实测状态和坐标/限位设置。控制台ACTUAL可能是最近缓存的采样，末位波动不等于肉眼可见运动。

```bash
project/.venv/bin/python -E -s project/Assets/Scripts/rm75_continuous_replay.py \
  --sdk-orientation deployment/logs/实际的joystick-continuous日志.jsonl
```

该回放只调用本地SDK旋转数学、校验目标规划，不重发机器人运动。其他日志类型用对应回放器，不能混用；原日志中的`completed`并非完整IK/网络/机械响应延迟测量。

新设备逐项记录：四轴方向、按Grip空输入、摇杆回中、Grip释放停止、同一Grip越过旧预算、边界HOLD反向恢复、追踪/网络中断停止及release-to-rearm。运动中失联验证需由现场人员在受控小范围内安排，不能用离线假机械臂测试声称已经现场通过。

完整离线测试：`bash 启动.sh test`。正常主机要求UDP测试不能跳过时：

```bash
RM75_REQUIRE_UDP=1 bash 启动.sh test
```

## 10. 常见问题

| 现象 | 检查/处理 |
|---|---|
| 无数据 | APP前台/佩戴追踪、同Wi-Fi、configure-pico、AP隔离、防火墙；USB只用于安装配置 |
| 模型/摇杆菜单不见 | 打开project/工程，等导入完成，检查Console编译错误与PICO包路径；不是Unity Hub菜单 |
| 运动几厘米后必须重新Grip | 确认用joystick-continuous；旧joystick-live的30°累计预算会有此行为；读HOLD具体原因 |
| 连续模式也HOLD | 查绝对边界/奇异/旋转范围；反向退回；不视为网络或Grip预算问题 |
| TARGET固定、ACTUAL末位抖动 | 看发送计数、状态及实测误差；数值噪声不直接代表真实位移 |
| 端口已占用 | 正常退出旧input/preview/live/bridge，不同时运行多个入口 |
| 状态读取/目标过期/位置误差FAULT | 释放Grip、保存日志，查有线连接/控制器状态/反馈耗时；不要放宽超时或跟踪阈值 |
| 新电脑doctor缺少APK报告 | 在本机配置/构建；旧电脑的路径和证明不可复用 |

第三方获取方式和许可见[第三方依赖](第三方依赖.md)；已做与未做的验证见[版本记录](版本与验证记录.md)。
